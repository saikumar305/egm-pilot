Spec-driven development for Claude Code

Design with an elephant.

Engineers use this open-source plugin to draft specs with deep-context agents, then stress-test them with zero-context subagents before any code is written.

See the skills

Design with context. Review with fresh eyes.

The approach is credited to Dave Rensin. Read his article on the Elephant, Goldfish and the new golden age of software engineering.

🐘 Elephant full context

Deep-context agents load system history, architecture and user journeys. They brainstorm with you and draft the spec.

🐠 Goldfish zero context

Stateless subagents read only the draft and the live source code. They have no memory of the conversation, so they can't agree by default.

You make the architectural decisions and approve the spec before anything is implemented.

Go from an idea to a verified spec.

  1. 1

    Brainstorm

    /egm:egm-brainstorm

    Test the idea and write a concept brief.

  2. 2

    Draft

    /egm:egm-draft

    Turn the brief into a design document, one section at a time.

  3. 3

    Review

    /egm:egm-review

    Fresh reviewers run five stages over the design. Resolve the findings.

After the coding agent has built against the spec, check for drift with /egm:egm-drift-report.

EGM Autopilot: Jira ticket or idea to reviewed merge request

Give it an assigned Jira ticket, or describe an idea with --idea. It plans, builds and reviews the change in your own session, with your own logins, and opens a Draft merge request in your name. You review and merge it.

  • Worktrees
  • Spec
  • Spec review

  • Code review
  • Draft MRs
  • You review
  • Risk lanes. Auth, payments, schema, public APIs and cross-repo contracts force a human spec approval.
  • Ticket or idea. --idea "<text>" starts without a ticket; --ticket <PROJECT> files one once the spec is reviewed.
  • Two modes. Unattended, or --interactive: a live Q&A where you approve the spec, each unit, every review finding and the MR.
  • Your repo's standards. Code follows a standards pack built from the repo's own instructions, style guides and conventions, and a reviewer checks every diff against it.
  • Optional multi-repo. One repo by default; attach more with --repos from anywhere on disk. Other likely affected repos are only suggested.
  • Stacked MRs. Large tickets become small units, each reviewed on its own, raised as linked Draft MRs.
  • Parked questions. It asks on Jira with multiple-choice answers (1B 2A) and resumes with --resume.
  • Your repo's MR template. Only verified checks are ticked; unknowns are marked, never guessed.
  • Guardrails. It never merges, approves or force-pushes, and Jira text is treated as untrusted input.

Install the plugin

Requires Claude Code 2.1.271 or later.

From the marketplace

claude plugin marketplace add google/elephant-goldfish-model && claude plugin install egm@egm

From a local copy

claude --plugin-dir /path/to/elephant-goldfish-model

Use a uniquely named copy if an egm plugin is already installed. Then enable it with claude plugin enable egm@egm.

Autopilot also needs git, jq, glab logged in as you, and the Atlassian connector in Claude Code. Run /egm:egm-init once to register your repos.
